# gen_only_no_context
#
# Same decode-loop measurement as gen_only, but the gen worker fabricates its own
# KV blocks, so no ctx fleet is allocated at all. aggr- prefix, not disagg-: the
# prefix names the launch path, and this mode runs one pytest that owns the gen
# worker, the proxy and the client -- the same single-pytest path ctx_only takes
# out of a disaggregated yaml. The yaml is unchanged and shared with the disagg
# ids; num_ctx_servers/num_gen_servers are overridden to (0, 1) by the mode.
#
# Losing gen_only's ctx fleet does NOT lose cache-transceiver coverage here: every
# config below also runs disagg-e2e- in this same list, and e2e is what exercises
# the KV transfer. What gen_only adds over gen_only_no_context is real KV arriving
# at the gen worker, which e2e already covers for these configs.
#
# NOTE: baselines do not carry over. s_benchmark_mode is an OpenSearch match key,
# so a case that moves here starts a fresh baseline lineage and its decode metric
# is un-gated until enough history accumulates (<2 versions reports
# `insufficient`). That is the price of the move, and the reason the list above is
# not emptied wholesale.
